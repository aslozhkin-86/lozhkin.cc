## Product and Visual Direction

- The homepage and project pages use the shared `#161616` board, the same sparse CSS dot grid, and bright green accents. The grid uses one shared color, spacing, and origin from `source/styles/tokens.css` and fills the viewport on every page. Its fixed layer moves upward at 18% of scroll speed; reduced-motion preference keeps it stationary. The m10 and Birmarket overviews and the Birmarket growth article reuse `DotParallax` with `#888995` secondary text.
- `source/styles/tokens.css` is the sole shared color and typography token file. It defines Inter body (18/26), Body bold (the same 18/26 with weight 700), Instrument Serif headings, LORE accents, and semantic color roles. Black and inverse text are `#161616`; inverse secondary text is `#595D65`. Page CSS owns layout and responsive behavior, not duplicate color/type systems.
- The homepage uses Instrument Serif for display headings, Inter for body text, and the existing bundled LORE Alternates for handwritten accents on retained sections. Inter 4.1 is self-hosted from the owner's `Inter-4.1/web/InterVariable.woff2` as `source/public/fonts/InterVariable.woff2`, with its SIL Open Font License beside it. Instrument Serif and its license are also in `source/public/fonts/`.
- LORE Alternates is retained for handwritten accents. EB Garamond and its old font asset were removed because no live page uses them.
- Keep decorative dots generated in CSS. Do not export dot-pattern backgrounds from Figma.
- Keep `filter: brightness()` and `drop-shadow()` for interaction feedback. Do not replace them with `box-shadow`.
- Keep editable site assets in `source/public/`. The repository-root `public/` is generated by `scripts/sync-static.mjs` for static hosting and must not be edited by hand.

## Shared Interaction Architecture

- `HoverTiltIcon` owns reusable icon perspective, image-shaped glare, and pointer tracking. Callers supply the image path and accessible label; optional numeric settings reuse the Playground's motion controls. At 1080 px and above with a fine pointer it tilts on hover. Below that width, tapping the icon plays a repeatable 620 ms wobble; keyboard activation works at every width. Reduced-motion preference leaves the icon still.

- `BeforeAfter` is a reusable image comparison slider. It accepts optional before/after image paths and labels, defaults to the Figma placeholder colors, and uses a native range input so pointer, touch, and keyboard users can move the divider. Its frame has 40 px smooth corners at all widths, and the central divider casts a compact shadow to separate the two images. Its handle icon is a local Figma asset in `source/public/design-system/`. The Playground shows the shared component. The Birmarket homepage gallery instead uses two `SelectPill` buttons to choose the old screenshot or the new video/still state.
- `PageCloseLink` is the shared close/back control for project overview and standalone case pages. It owns the 40 px hit area, 32 px SVG, icon-only opacity hover, focus outline, and reduced-motion behavior. Page styles only position it; each page supplies its return URL and accessible label.
- Cross-page navigation uses native anchors. The static production host serves prerendered HTML, while vinext client-side `Link` navigation fails on the published site; a full document navigation also restarts the destination page's entrance animation.

- Reuse `DraggableCardStack` and `useCardStack` for card stacks. Do not copy their pointer logic into individual sections.
- Reuse `DraggableIcon` and `useDragCollection` for loose image/icon interactions.
- Use `useLayerOrder` for z-index ordering. The last object manipulated should appear on top.
- Speaking cards retain their mobile cycling behavior: dragging a card far enough cycles it to the back and returns it to its original coordinates.
- A returning mobile card must not block the next card from being dragged immediately.
- On desktop, the retained Speaking cards are draggable and remain at their dropped coordinates.
- On mobile, service and company icons are not draggable. Their tooltips open on tap. Company details use an animated, non-modal popover above the tapped icon, positioned in document coordinates so it scrolls with the page. Keep the close button and existing dimensions, allow native scrolling and normal keyboard navigation, and clamp to the screen gutters.
- Tooltips appear above all page objects, centered above their icon. Overlap with other content is intentional.
- Preserve the delayed desktop tooltip appearance and existing hover rotation/brightness behavior.
- `SpeakingSection` reveals its desktop cards from a stacked deck once when the section reaches the reveal threshold. Scrolling upward must not restack them.

## Responsive Behavior

- Content modules are centered with a maximum desktop width of 1440 px; some reading columns and media rows use narrower caps. The homepage hero and full-width sections, plus the project and editorial case heroes, stretch across the viewport. The shared fixed dot grid fills the viewport on all pages.
- Use one responsive switch for visible pages: desktop layout starts at 1080 px, and narrower tablet widths use the mobile layout and interaction rules. Do not add a separate tablet composition. The Birmarket case preview and other `ProjectStoryCard` media use a 4:3 frame in the mobile layout. Its overview places the supplied sticker in the third column on desktop and after the text groups in the mobile layout.
- Keep page-to-page navigation and hash targets immediate. Do not set global `scroll-behavior: smooth`; it makes route changes visibly scroll from the previous page position.
- Preserve a practical gap between section titles and their visual content. Prefer additional section height or wrapping over overlapping content.
- Mobile section titles use the shared `--portfolio-mobile-section-title-*` tokens.
- Do not force ordinary content sections to fill the viewport. The Hero is the intentional viewport-height exception.
- The new Hero uses a single centered portrait and copy at desktop and mobile widths; its inline navigation wraps on narrow screens.
- Company logos use fixed 81 × 81 px image boxes on desktop and mobile. Serve their small original PNGs (134–200 px) directly to avoid requesting oversized image variants.
- Keep mobile card decks compact, with the existing 10 px stack offset unless the user requests another value.

## Scope Discipline

- When the user limits a request to content, spacing, or one section, change only that scope. Preserve card coordinates, dragging, hover behavior, and unrelated breakpoints.
- Prefer adapting an existing shared component over building a second implementation of the same interaction.
- Treat Figma as the visual source when the user supplies a node link, but adapt its fonts and colors to the tokens already used by the project.
- Keep unfinished project links inert or absent until the user supplies their destinations.
